## Entry, proof and recovery

Before each production change, identify the exact active source/configuration, permitted deployment method, recoverable backup and safe reversal. Use the current deployed version as the baseline; local source drift must not be uploaded wholesale. Code and tests run from checksum-verified non-cloud staging. Preserve public route behaviour, account grants and payment settings. A stopped service is not assumed safe to start until its startup actions and current role are reviewed.

Use isolated fixtures for negative/expiry/reuse tests, then prove the normal owner path through the actual browser and delivered factor. Do not fabricate a signed production credential or read a code from server storage as a substitute for delivery. Only explicitly named synthetic/owner accounts may be involved. Do not open any real family record to prove identity.

Each freeze note records the row, plain change, deployed file/config version, exact browser/API evidence and limits, recovery, the reviewed public live-payment lock and the fact that imported tenancies were neither used nor emailed. Failed proof stops the row; do not stack another production change on it. Preparing read-only source/provenance evidence for later rows is allowed; implementing them waits for their turn.
