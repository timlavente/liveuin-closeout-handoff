# AUTH02 / 9095: create the restart review from evidence

This procedure is for the engineer using the already authenticated root connection. It is not owner sign-in proof and does not finish AUTH02. No command in the configuration classifier sends email, creates a code/account/session, queries a customer database or starts/stops a service.

1. Copy the pinned package into a root-owned directory below `/root/` with mode0700. Check the package manifest, the exact candidate/fallback hashes, and the independent test evidence. Do not copy secret configuration or database backups to the local workstation.
2. Finish the existing startup review. It must cover the selected application imports, declaration-time expressions, alias/generated routing, the exact DSN wrapper and `ensure_venv.sh`. The latter can rebuild a virtualenv/install dependencies; do not assert a safe restart until its actual configured mode and fast-path requirements rule out that behavior. Keep the source hashes and specific evidence references. No live application import is used as a read-only check.
3. Run the pinned `classify-restart-config.py --compare-credentials` as root. It compares the manager-global environment, loaded unit environment and every configured EnvironmentFile with the running process, applies final UnsetEnvironment rules including required absence, and requires PAMName to be empty. It applies only the already reviewed wrapper's four DSN exports and optional country DSN export. Configured LoadCredential bytes are compared with the current service's loaded credential bytes only in memory. It prints equality/counts or differing environment variable names, never values or credential digests. Unsupported syntax or any mismatch stops; classify it rather than changing a setting to make the check pass.
4. Run the pinned `prestart-fastpath-probe.py` against that fresh configuration result, saving its detailed proof inside the root-private package. It checks the actual configured ExecStartPre identity and exact prestart commands, then proves only the seven existing third-party imports with product imports, file writes and network use denied. A failure stops before any verdict or activation. After a successful result, run the pinned `build-startup-verdict.py` with the externally checked package-manifest hash and the private probe-result path. The builder checks every packaged file, the successful configuration/probe versions, all20 Ops entry/local module source pins,31 direct deployed modules, six concrete constructor/path-getter sources,14 reconciled resident payloads and the exact wrapper; it also binds the tested prestart/library sources. It excludes the API file being replaced, whose baseline/candidate/fallback are pinned separately. Only then does it create `deployment/startup-verdict-9095.json` with the bounded review conclusions. This is not an exhaustive platform guarantee or owner authentication proof. Do not hand-create true values to bypass an unresolved condition.
5. Run the same classifier with `--compare-credentials --startup-verdict <root-private-path> --write-review`. Only a successful fresh configuration comparison and a matching startup verdict create `deployment/restart-review-9095.json`. That file is root-private because it contains fingerprints of protected configuration. Do not export it. The classifier independently binds the helper/spec/candidate/fallback hashes, baseline PID, protected configuration hashes, startup-source hashes and static service action descriptors. It also retains one aggregate manager-configuration fingerprint only in this root-private review and records credential-source device/inode/size/mtime/ctime for restart-time drift checks. No global environment values or per-credential digests are exported. Runtime action timestamps/PIDs/exit results are deliberately excluded.
6. Independently review the exact activation controller and its failure tests, then use `activate-9095.py --activate`. It runs the pinned seven-library fast-path proof before the first source change and immediately before each candidate/fallback restart; a failed proof cannot run the automatic dependency installer. It makes protected on-server source/configuration backups and per-file consistent SQLite backups, compiles the candidate, installs only the one9095 API file and restarts only the named Ops service. Backups are root-only, not claimed encrypted or cross-database atomic. Database restore is never automatic.
7. Its success means safe negative checks passed and owner proof is pending. Reload the existing owner Ops session and perform one normal owner code request/sign-in through the visible browser. Do not inspect another family's records. If that positive proof fails, `activate-9095.py --recover` works from the owner-proof-pending state and installs the pinned closed fallback. It never restores the original unsafe API. If reviewed configuration/source changes, the controller does not restart it. It stops only when the reviewed stop actions still match; otherwise it reports manual root recovery required.

The controller handles TERM/HUP by entering bounded closed recovery after a write. A hard kill or host loss can interrupt any process; its root-private durable state records pending recovery so the engineer can rerun `--recover`. This does not promise an impossible atomic restart across power loss.

The9095 component prevents new unsafe issuance and verification of incompatible pending challenges. Existing issued sessions are intentionally untouched. It does not prove platform-wide closed admission. The9098/frontend cohort decision, full account/role proofs and remaining frozen rows remain separate gates.

The environment order is grounded in the official [systemd execution environment documentation](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html#Environment%20Variables%20in%20Spawned%20Processes) and [Manager.Environment contract](https://www.freedesktop.org/software/systemd/man/latest/org.freedesktop.systemd1.html). This is a comparison of the declared launch inputs and the known wrapper output; generated per-invocation values such as the new PID are not claimed identical.
